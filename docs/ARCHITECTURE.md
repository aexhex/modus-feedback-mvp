# Техническая концепция

## Компоненты

```
Браузер (SPA, ES-модули)  ──HTTP/JSON──▶  Node.js сервер (node:http)
                                           ├─ routes.js     REST API, конверт { ok, data, error }
                                           ├─ access.js     политика доступа (RBAC + владение)
                                           ├─ routing.js    маршрутизация обращений
                                           ├─ tickets-*.js  жизненный цикл, SLA, комментарии
                                           ├─ analytics.js  показатели, повторяющиеся темы
                                           ├─ escalation.js фоновая эскалация просрочек (раз в минуту)
                                           ├─ export.js     экспорт реестра в CSV
                                           ├─ settings.js   настраиваемые сроки SLA
                                           ├─ collab.js     наблюдатели, приглашения, задача Битрикс24 (имитация)
                                           ├─ home.js       данные главной страницы по ролям
                                           ├─ reports.js    отчёты о внедрении, рейтинг авторов
                                           ├─ surveys.js    опросы сотрудников
                                           ├─ client-feedback.js  публичная форма для клиентов, NPS
                                           ├─ votes.js, digest.js голосование за идеи, сводка недели
                                           ├─ user-import.js, demo-reset.js  импорт из CSV, сброс демо-данных
                                           ├─ templates.js, audit.js  шаблоны ответов, журнал действий
                                           ├─ notifications.js  уведомления + журнал имитации Битрикс24
                                           └─ db.js ──▶ SQLite (node:sqlite) + data/uploads/
```

## Выбор технологий

| Решение | Почему |
|---|---|
| Node.js 24+, без внешних зависимостей | Запуск одной командой без `npm install`; нет цепочки поставок для проверки; встроенные `node:sqlite` и `node:test` |
| SQLite | Реляционная модель, транзакции, ноль администрирования для MVP. Схема переносится на PostgreSQL без изменений логики |
| Vanilla JS + ES-модули | Нет шага сборки; интерфейс простой. При росте — React/Vue |
| Хэш-роутинг SPA | Работает на любом статическом хостинге / за любым прокси |
| Графики на чистом SVG | Без библиотек; одна ось на график, подсказки, табличный вид, цвета проверены на различимость при дальтонизме в обеих темах |

## Модель данных

| Таблица | Назначение |
|---|---|
| `users` | Сотрудники: роль, подразделение, доступность (замещение) |
| `categories` | Категории + правило маршрутизации (основной, резервный) |
| `tickets` | Обращения: тип, категория, статус, приоритет, автор, анонимность, ответственный, результат, SLA-сроки, дубликат |
| `events` | Неизменяемый журнал: создание, назначение, смена статуса, комментарии, внутренние заметки, вложения, поддержка |
| `supports` | «Поддержать» (уникально на пару обращение-сотрудник) |
| `attachments` | Метаданные файлов; файлы на диске под случайными именами |
| `notifications` | Внутренние уведомления |
| `outbox` | Журнал имитации: вызовы Битрикс24 `im.notify` и `tasks.task.add`, которые были бы отправлены |
| `escalations` | Эскалации: одна запись на обращение и вид просрочки, время последнего напоминания и их число |
| `watchers` | Наблюдатели обращения: приглашённые коллеги и подписавшиеся |
| `settings` | Настройки, изменяемые администратором (сроки SLA, праздничные дни) |
| `impl_reports` | Отчёт о внедрении: что сделано и какой эффект |
| `reply_templates` | Шаблоны ответов, редактируемые администратором |
| `audit_log` | Журнал действий администратора |
| `surveys`, `survey_questions`, `survey_answers` | Опросы сотрудников и ответы |
| `client_feedback` | Отзывы клиентов: оценка 0–10, текст, необязательные контакты |
| `idea_votes` | Голоса за идеи: сколько голосов (1–3) сотрудник отдал идее; наружу отдаётся только сумма |
| `feedback` | Оценка результата автором: решён / не решён, комментарий |
| `sessions` | Сессии (случайный 256-битный токен, срок жизни 12 часов проверяется на сервере) |

История строится из `events` — это аудит-лог и основа будущей аналитики «время в статусе».

## Жизненный цикл

```
new ─▶ in_review ─▶ in_progress ─▶ implemented ─▶ closed
 │        │  ▲          │
 │        ▼  │          ▼
 └─▶ need_info ◀────────┘          (ответ автора → in_review автоматически)
 └─▶ rejected ─▶ closed / повторное рассмотрение
```

Допустимые переходы — `TRANSITIONS` в `src/config.js`. Итоговые статусы требуют результата. Первый ответ фиксируется при первой смене статуса или первом публичном комментарии обработчика.

**SLA** считается в рабочих часах: суббота, воскресенье и праздничные дни из списка `HOLIDAYS` в `src/config.js` (по московскому времени) пропускаются, 24 часа = 1 рабочий день. Сроки по приоритетам администратор меняет в интерфейсе (таблица `settings`); новые значения действуют для обращений, созданных после изменения.

**Эскалация:** фоновая задача раз в минуту ищет обращения с нарушенным сроком, уведомляет ответственного и руководителей и пишет запись в историю. Срок первого ответа и срок решения эскалируются независимо. Пока просрочка не устранена, напоминание повторяется каждые 2 рабочих дня (`ESCALATION_REMINDER_HOURS`); таблица `escalations` хранит время последнего напоминания.

## Управление доступом

| Действие | Сотрудник | Ответственный | Руководитель | Админ |
|---|---|---|---|---|
| Создать, комментировать своё | ✓ | ✓ | ✓ | ✓ |
| Видеть обращение | свои | свои + назначенные + где он наблюдатель | все | все |
| Пригласить коллегу, создать задачу Б24 (имитация) | — | назначенные | все | все |
| Менять статус/приоритет, внутренние заметки | — | назначенные | все | все |
| Переназначить | — | — | ✓ | ✓ |
| Аналитика | — | — | ✓ | ✓ |
| Читать и комментировать опубликованное в ленте идей | ✓ | ✓ | ✓ | ✓ |
| Отчёт о внедрении | — | назначенные | все | все |
| Создать опрос, видеть результаты, отзывы клиентов, отчёт за период | — | — | ✓ | ✓ |
| Категории, маршрутизация, пользователи, сроки, праздники, шаблоны, журнал | — | — | — | ✓ |

Проверки выполняются на сервере (`src/access.js`); интерфейс лишь скрывает недоступные действия.

## Безопасность

- Сессия в cookie `HttpOnly; SameSite=Strict`; мутации принимают только `application/json` (защита от CSRF через формы).
- Параметризованные SQL-запросы; валидация всех входных полей и длины на сервере.
- XSS: интерфейс вставляет пользовательский текст только через `textContent`; CSP `default-src 'self'`, без inline-скриптов; `X-Frame-Options: DENY`, `nosniff`.
- Вложения: белый список расширений, лимит 5 МБ, случайные имена файлов, отдача как `application/octet-stream` с `Content-Disposition: attachment`, доступ только при праве на обращение.
- Защита от выхода за пределы каталога статики; ограничение размера тела запроса; rate limit на изменяющие запросы (60/мин на пользователя).
- Ошибки не раскрывают внутренние детали; чужие обращения отдаются как 404.
- Экспорт CSV: значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются — защита от выполнения формул в Excel.
- Анонимные обращения: имя и подразделение не отдаются API никому, кроме автора; фильтр по подразделению их исключает; в рейтинге авторов они не участвуют.
- Лента идей: обращение становится видимым всем только по решению автора; автор и ответственный могут снять публикацию. Читатели и подписчики не видят внутренние заметки и не могут прикладывать файлы. Рейтинг авторов строится только по опубликованным неанонимным обращениям.
- Опросы: сводные результаты доступны только после закрытия опроса и при трёх и более ответивших (иначе по разнице итогов «до» и «после» можно вычислить отвечавшего); закрытый опрос не открывается заново; тексты показываются при трёх и более непустых ответах и отсортированы по алфавиту.
- Публичная форма для клиентов (`POST /api/public/feedback`) — единственный изменяющий метод без входа: строгая проверка полей, поле-ловушка от ботов, отдельный лимит 5 запросов в минуту с адреса и общий предел 300 отзывов в сутки; оценка принимается только числом. Для открытого интернета нужны капча и модерация.
- Отключённый пользователь не может войти, его сессии удаляются, ему нельзя назначить обращение, а его открытые обращения автоматически переходят следующему по правилу категории; изменения настроек записываются в журнал действий.
- Сброс демо-данных (`POST /api/admin/demo-reset`) доступен только администратору и только в демо-режиме, который включается явно (`DEMO_MODE=1`; так делают `npm start` и `npm run reset`, в Docker-образе он выключен), иначе метод отвечает 403. Очистка и повторное заполнение идут одной транзакцией; удаляются все сессии и только файлы вложений.
- Журнал имитации Битрикс24: у анонимного обращения скрыты имена всех получателей уведомлений, чтобы автора нельзя было вычислить по разнице.
- Импорт пользователей принимает до 500 строк и 60 тысяч символов; строки с ошибками не добавляются и возвращаются с причиной.
- Приглашение в обсуждение одинаково обрабатывает автора анонимного обращения и любого другого коллегу, чтобы по ответу нельзя было вычислить автора.
- **Промышленная версия:** HTTPS, SSO вместо демо-входа, продление сессий при активности, резервное копирование БД, журнал доступа, шифрование диска с вложениями, антивирусная проверка файлов.

## Интеграции (предложение; в MVP реальных вызовов нет)

| Система | Цель | Данные и направление | Способ | Уточнить |
|---|---|---|---|---|
| Битрикс24 — авторизация | Вход корпоративной учётной записью | Б24 → система: ID, ФИО, подразделение | OAuth 2.0 приложения Б24 | Тип портала (облако/коробка), права приложения |
| Битрикс24 — уведомления | Уведомлять там, где работают сотрудники | Система → Б24: текст, ссылка, получатель | REST `im.notify`. **В MVP имитируется:** `src/notifications.js` пишет вызов в таблицу `outbox`, журнал виден администратору | Разрешено ли приложению писать в чаты |
| Битрикс24 — задачи | Исполнение реализуемых предложений в привычном инструменте | Система → Б24: задача из обращения; Б24 → система: статус задачи | REST `tasks.task.add` + вебхук событий. **В MVP имитируется:** кнопка в карточке пишет вызов в `outbox`, обратной связи по статусу задачи нет | Проекты/группы для задач, сопоставление статусов |
| 1С | Актуальный справочник сотрудников, подразделений, руководителей | 1С → система, раз в сутки | Выгрузка через HTTP-сервис / OData 1С | Конфигурация (ЗУП/УТ), где ведётся оргструктура |

Принцип: система остаётся источником правды по обращениям; интеграции добавляются как адаптеры, не меняя ядро.

## Масштабирование и развитие

- **Нагрузка:** ожидаемый объём (сотни обращений в месяц) SQLite выдерживает с запасом. Для нескольких инстансов — PostgreSQL, сессии в БД уже есть, вложения — в S3-совместимое хранилище.
- **Поиск дубликатов:** заменить префиксный стемминг на полнотекстовый поиск PostgreSQL (русская морфология) или эмбеддинги.
- **SLA:** часы работы, автоматическая загрузка производственного календаря (сейчас администратор правит список вручную).
- **Новые типы обратной связи** (клиенты, опросы): отдельные сущности и права поверх того же журнала событий; внешний контур — отдельный публичный интерфейс без доступа к внутренним обращениям.
