# Сценарий защиты на 5 минут

Перед показом: войти администратором → «Настройки» → «Сбросить демо-данные» (или `npm run reset`), окно браузера на http://localhost:3000.
Роль меняется кнопкой «Сменить роль» справа вверху.

| Время | Роль | Что показать | Что сказать |
|---|---|---|---|
| 0:00–0:30 | Экран входа | Четыре роли | Проблема: предложения теряются в переписке, автор не знает судьбу обращения, руководитель не видит повторов. Вход здесь демонстрационный, в промышленной версии — SSO Битрикс24 |
| 0:30–1:30 | **Сотрудник офиса** | Главная → «Новое обращение» → категория «Хранение документов» → тема «Не найти актуальную инструкцию в общих папках» → справа появляется A-019 → отправить | Подача за минуту. Система сама находит похожие темы: можно поддержать чужую вместо дубля. Обращение сразу получило номер, срок и ответственного — «ничьих» обращений не бывает |
| 1:30–2:30 | **Администратор документов** | Главная («Ждут первого ответа») → обращение → «Рассмотрение» → шаблон ответа → «Ожидает уточнения» с вопросом. Показать «Доску задач» и флажок «Внутренняя заметка» | Ответственный видит только свою очередь. Уточнение — один шаг; после ответа автора обращение само вернётся на рассмотрение. Закрыть без зафиксированного результата нельзя |
| 2:30–3:10 | **Сотрудник офиса** | Открыть A-017 → мотивированный отказ → «Нет, не решён» | Автор всегда получает ответ, даже отказ — с причиной. Оценка автора даёт метрику качества, а не только скорости |
| 3:10–4:10 | **Директор по развитию** | Главная: показатели и график → «Все обращения» → «Только просроченные» (4 шт.) → открыть A-007, запись «Эскалация» в истории → «Экспорт в Excel» → «Аналитика» | Сроки считаются в рабочих днях. При просрочке руководитель получает уведомление автоматически. В аналитике — показатели из ТЗ, повторяющиеся темы и возможные дубликаты |
| 4:10–4:40 | **Администратор системы** | «Настройки»: правило «основной → резервный», флажок «на месте», сроки SLA, журнал «Уведомления в Битрикс24 — имитация» | Маршрутизация настраивается без программиста. Интеграция с Битрикс24 показана как имитация: видно, какие вызовы ушли бы на портал |
| 4:40–5:00 | Любая | «Лента идей» → «Доска улучшений»: отчёт о внедрении, автор месяца | Идеи обсуждают все, а не только автор с ответственным. Прозрачность результата — главный мотив подавать предложения. Дальше: SSO и реальный обмен с Битрикс24, справочник из 1С |
| Если останется время | **Директор по развитию** | «Сводка недели» → «Разослать»; «Лента идей» → «Сначала популярные»; «Опросы» → результаты; «Отзывы клиентов» → NPS; «Аналитика» → «Отчёт за период» → печать | Тот же продукт закрывает опросы сотрудников и обратную связь клиентов — направления развития из ТЗ уже работают |

## Вероятные вопросы жюри

- **Что будет, если ответственный в отпуске?** Администратор снимает флажок «на месте» — новые обращения уходят резервному, а если его нет — руководителю.
- **Насколько анонимна анонимная подача?** Имя и подразделение скрыты от всех, включая руководителей; в выборку по подразделению такие обращения не попадают. Автор при этом видит статус и отвечает на уточнения. В сводной статистике подразделение учитывается.
- **Как система не даёт обращению потеряться?** Автоназначение, сроки, подсветка просрочек, автоматическая эскалация руководителю, обязательный результат при закрытии.
- **Почему без фреймворков и зависимостей?** Запуск одной командой и никакой цепочки поставок. Схема данных переносится на PostgreSQL без изменения логики.
- **Как проверено?** 127 серверных тестов (покрытие около 98%) и 29 сквозных тестов интерфейса; настроен их автозапуск на GitHub при каждой отправке кода.
