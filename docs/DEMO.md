# Сценарий защиты на 5 минут

Перед показом: `npm run reset` (чистые демо-данные), окно браузера на http://localhost:3000.
Роль меняется кнопкой «Сменить роль» справа вверху.

| Время | Роль | Что показать | Что сказать |
|---|---|---|---|
| 0:00–0:30 | Экран входа | Четыре роли | Проблема: предложения теряются в переписке, автор не знает судьбу обращения, руководитель не видит повторов. Вход здесь демонстрационный, в промышленной версии — SSO Битрикс24 |
| 0:30–1:30 | **Сотрудник офиса** | «Новое обращение» → категория «Хранение документов» → тема «Не найти актуальную инструкцию в общих папках» → справа появляется A-019 → отправить | Подача за минуту. Система сама находит похожие темы: можно поддержать чужую вместо дубля. Обращение сразу получило номер, срок и ответственного — «ничьих» обращений не бывает |
| 1:30–2:30 | **Администратор документов** | Колокольчик → новое обращение → «Рассмотрение» → «Ожидает уточнения» с вопросом. Показать флажок «Внутренняя заметка» | Ответственный видит только свою очередь. Уточнение — один шаг; после ответа автора обращение само вернётся на рассмотрение. Закрыть без зафиксированного результата нельзя |
| 2:30–3:10 | **Сотрудник офиса** | Открыть A-017 → мотивированный отказ → «Нет, не решён» | Автор всегда получает ответ, даже отказ — с причиной. Оценка автора даёт метрику качества, а не только скорости |
| 3:10–4:10 | **Директор по развитию** | «Все обращения» → «Только просроченные» (4 шт.) → открыть A-007, запись «Эскалация» в истории → «Экспорт в Excel» → «Аналитика» | Сроки считаются в рабочих днях. При просрочке руководитель получает уведомление автоматически. В аналитике — показатели из ТЗ, повторяющиеся темы и возможные дубликаты |
| 4:10–4:40 | **Администратор системы** | «Настройки»: правило «основной → резервный», флажок «на месте», журнал «Уведомления в Битрикс24 — имитация» | Маршрутизация настраивается без программиста. Интеграция с Битрикс24 показана как имитация: видно, какие вызовы ушли бы на портал |
| 4:40–5:00 | Любая | «Доска улучшений» | Прозрачность результата — главный мотив подавать предложения. Дальше: SSO и задачи в Битрикс24, справочник из 1С, клиентская обратная связь |

## Что реализовано, а что имитация

| Реализовано и работает | Имитация | Только в планах |
|---|---|---|
| Подача, маршрутизация, статусы, SLA в рабочих днях, эскалация, уточнения, анонимность, похожие и дубликаты, оценка автора, аналитика, экспорт, роли и права | Отправка уведомлений в Битрикс24 (журнал вместо реального вызова); вход без пароля вместо SSO | Задачи в Битрикс24, справочник из 1С, e-mail, клиентская обратная связь и опросы |

## Вероятные вопросы жюри

- **Что будет, если ответственный в отпуске?** Администратор снимает флажок «на месте» — новые обращения уходят резервному, а если его нет — руководителю.
- **Насколько анонимна анонимная подача?** Имя и подразделение скрыты от всех, включая руководителей; в выборку по подразделению такие обращения не попадают. Автор при этом видит статус и отвечает на уточнения. В сводной статистике подразделение учитывается.
- **Как система не даёт обращению потеряться?** Автоназначение, сроки, подсветка просрочек, автоматическая эскалация руководителю, обязательный результат при закрытии.
- **Почему без фреймворков и зависимостей?** Запуск одной командой и никакой цепочки поставок. Схема данных переносится на PostgreSQL без изменения логики.
- **Как проверено?** 58 серверных тестов (покрытие около 97%) и 7 сквозных тестов интерфейса; настроен их автозапуск на GitHub при каждой отправке кода.
